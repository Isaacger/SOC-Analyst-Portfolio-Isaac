## 1. Executive Summary

An Exchange security alert was generated under detection rule SOC282 – Phishing Alert – Deceptive Mail Detected (Event ID 257).

The alert involved a suspicious email with the subject **"Free Coffee Voucher"**, sent from `free@coffeeshooop.com` to `Felix@letsdefend.io`.

Initial email inspection identified a hyperlink embedded within the message content. The URL directed the recipient to a ZIP archive hosted on an Amazon S3 endpoint. Threat intelligence analysis using platforms such as VirusTotal and ANY.RUN identified `Free_coffee.zip` as malicious.

The email security control recorded the message as Allowed, confirming that it was delivered to the recipient.

Further investigation of the Log Management and Processes tabs established that Felix's host accessed the malicious URL, downloaded the archive and executed the malware.

During endpoint investigation, a file hash and a suspicious destination IP address associated with outbound communication were collected. The destination IP was identified as being associated with malicious web infrastructure in the United States, with suspected Command and Control (C2) activity.

The malicious email was deleted from the recipient's mailbox, and endpoint containment was performed.

**Assessment:** True Positive – Phishing email resulting in confirmed malware download and execution, with suspicious outbound communication requiring further C2 and malware behaviour analysis.

## 7. Analysis & Findings

### 7.1 Email Security Analysis

The phishing email successfully bypassed the email security control and was delivered to the intended recipient.

The embedded URL directed the user to a malicious ZIP archive.

The combination of deceptive promotional content, a malicious download URL and successful delivery established the email as a phishing vector.

### 7.2 Endpoint Security Analysis

Endpoint logs confirmed that the recipient accessed the malicious URL, downloaded the archive and executed the malware.

This is significant because the incident progressed from an email-based threat to actual endpoint execution.

The endpoint should therefore be treated as affected, rather than simply exposed to a suspicious email.

### 7.3 Network Security Analysis

An outbound connection to a suspicious IP address located in the United States was identified during the investigation.

Threat intelligence associated the destination with malicious web infrastructure and suspected C2 activity.

Further investigation should establish:

- The process responsible for initiating the connection.
- Destination IP and port.
- Network protocol.
- Connection timestamps and frequency.
- DNS queries associated with the destination.
- Whether application layer communication supports C2 behaviour.
- Whether additional payloads or commands were exchanged.

### 7.4 Malware Behaviour Analysis – Pending Dynamic Analysis

Although malware execution has been confirmed, the complete behaviour of the payload has not yet been established.

The next investigation stage should focus on controlled dynamic analysis using an isolated malware-analysis environment.

Areas requiring investigation:

**Process behaviour**
- Parent and child process relationships.
- Process creation and command-line arguments.
- PowerShell, CMD or scripting interpreter activity.
- Process injection or unusual process manipulation.

**File system activity**
- Files created or modified.
- Extracted payloads.
- Additional downloaded files.
- Suspicious directories and temporary files.

**Persistence**
- Registry modifications.
- Scheduled tasks.
- Windows services.
- Startup entries.

**Network behaviour**
- DNS resolution.
- Outbound connections.
- C2 communication patterns.
- Additional payload downloads.
- HTTP/HTTPS requests and destination infrastructure.

**Potential impact**
- Credential access.
- System information collection.
- Privilege escalation.
- Lateral movement.
- Data exfiltration.

These behaviours must remain classified as unverified until supported by sandbox or endpoint evidence.

## 8. Verdict & Justification

**Final Verdict: TRUE POSITIVE**

The investigation confirmed that the detected phishing email was malicious and resulted in endpoint activity.

The following evidence supports the classification:

1. The email contained a malicious hyperlink.
2. The linked ZIP archive was identified as malicious through threat intelligence analysis.
3. The email security control allowed delivery to the recipient.
4. Endpoint logs confirmed access to the malicious URL.
5. The archive was downloaded and malware execution was observed.
6. Suspicious outbound communication to malicious infrastructure was identified.

The incident is therefore classified as a True Positive phishing-led malware execution incident.

**Outstanding investigation:** Dynamic Malware Analysis is required to establish the full capabilities and impact of the executed malware, and to validate the suspected C2 communication.

## 10. Detection & Prevention Recommendations

- Improve detection of deceptive promotional emails.
- Strengthen email gateway inspection of compressed attachments.
- Implement URL reputation checks and time of click protection.
- Correlate email delivery events with endpoint telemetry.
- Monitor browser downloads followed by suspicious execution.
- Detect unusual outbound connections initiated by newly created processes.
- Monitor suspicious PowerShell and command interpreter activity.
- Block confirmed malicious indicators through appropriate security controls.
- Review endpoint isolation and automated containment policies.

---

## 11. Lessons Learned

1. An email marked as Allowed does not mean that its content is safe.
2. Email parsing and hyperlink inspection are important parts of phishing investigations.
3. Threat intelligence platforms can help identify malicious files and URLs.
4. Correlating email events with endpoint logs is essential to establish whether a user interacted with a malicious message.
5. Malware execution changes the incident from a suspicious email into an endpoint security incident.
6. Hash collection and network IOC identification help support threat hunting and incident response.
7. Dynamic analysis is necessary to understand malware behaviour beyond initial execution.
8. C2 communication should be validated through process and network evidence rather than IP reputation alone.
9. Containment should be followed by verification and recovery.
10. MITRE ATT&CK techniques should reflect observed evidence rather than assumptions.
